# TrueType輪郭の閉じ損ない修正（2026-08-15）

## 症状

実書籍『ドキュメント　全国部落調査事件』の刊行用PDFで、`〇`(U+3007)や
`(`の輪郭の一部が**直線の弦に化けて欠けて見える**。目次(5pt)・本文(8pt)の
双方、PDF出力とPaged SVG出力の双方で同一箇所に再現した。Acrobatだけの
表示問題ではなく、PDFBoxの600/1200dpiラスタライズでもブラウザの
ネイティブSVG描画でも同じ欠陥が出る＝**生成された輪郭そのものが誤り**。

## 原因

`TrueTypeGlyphList.getGlyph()`の輪郭生成。旧実装は「輪郭の先頭2点を末尾へ
継ぎ足して閉じる」方式だったが、

- 残り1点になった反復で、既にシフト済みで**未初期化の隣接点**
  (`onCurve[1]`など)を読む
- その結果、**始点へ戻る最後の曲線を出力しないまま**輪郭を終える
- `closePath()`が始点まで直線を引くため、滑らかな曲線が弦になる

`GenEiChikugoMin3-R.ttf`の`〇`で実測した旧出力(AWTを参照とする):

```
AWT   : segs=24 quad=20   M 229.0 -650.9 / Q 116.2 -538.1 116.2 -379.9 / ...
pdfg2d: segs=22 quad=18   M 116.2 -379.9 (始点が誤り) / 最後の曲線が欠落
                          内側輪郭の末尾は Q 189.5 -69.3 287.1 -12.2 と
                          直前と同じ点へ戻る退化セグメント
```

## 修正

輪郭ごとの標準的な巡回アルゴリズムへ置き換えた。

1. 開始点を決める（先頭が曲線上ならそれ、そうでなければ末尾、双方とも
   制御点なら両者の中点）
2. 制御点を溜めながら輪郭を1周する（連続する制御点の間には曲線上の点が
   省略されているので中点を補う）
3. **制御点が残っていれば、開始点へ戻る最後の曲線を必ず描いてから**
   `closePath()`

## 検証

`〇`と`(`の両方で、pdfg2dのパスがAWT(java.awt.Font)のパスと一致することを
確認した（残差は丸め0.1のみ）。

```
修正後 pdfg2d: segs=24 quad=20  ← AWTと一致
```

診断ツールを追加: `copperpdf4/dev`の`glyphDiff`タスク
(`jp.cssj.test.image.GlyphOutlineDiffTool`)。同一フォントの同一文字を
pdfg2dとAWTで描き比べ、パスをダンプする。

copper4のimageTest（592文書）は**0差分**。既存コーパスの描画は変わらない
（欠陥の顕在化は輪郭の巡回パターンに依存し、コーパスでは踏んでいなかった）。

### フォント全グリフの突き合わせ

`glyphScan`タスク（`GlyphScanTool`）で、pdfg2dとAWTの輪郭を**64×64へ
ラスタライズして画素比較**した（セグメント数の比較では、AWTが閉じる直線を
明示的に出すのに対しこちらは`closePath()`に任せるため、形状が同じでも
構成が食い違う。画素で見るのが正しい）。

```
GenEiNombre-Roman.ttf: glyphs=313 checked=307 mismatched=42
  → 差はいずれも 4096画素中 1〜2画素、かつセグメント構成は一致
    (例: gid=8 pdfg2d(seg=53,quad=41) awt(seg=53,quad=41) diffPixels=1)
```

残差は1000/em換算の丸めによるもので、修正前の`〇`の
`seg=22 quad=18`(構造的な欠落)とは質が違う。**この字種では輪郭の欠落は
解消済み**と判断できる。

## 未対応（別件）

同ファイル調査中に、CFF(Type2 charstring)の`flex`系オペレータにも仕様
違反を見つけた。本件のフォントはTrueType(`glyf`)なので今回の症状とは無関係
だが、CFF/OTFフォントでは同種の輪郭崩れを起こす。

- `HFLEX`: 5点目・6点目のyが開始yへ戻らない（dy2ぶんずれる）
- `HFLEX1`: 6点目のyが開始yへ戻らない
- `FLEX1`: 最終点が`|dx|>|dy|`の分岐を実装しておらず、
  引数`d6`をxとyの**両方**に加えている

いずれも「浅い曲線」専用の命令で、円弧や括弧の側面に使われる。修正は別タスクとする。
